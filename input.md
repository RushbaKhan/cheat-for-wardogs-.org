Each later update: rebuild locally → **Create deployment** → upload new `dist`.
explanation:
It means: **every time you change the site, you build it on your PC again, then upload that new folder in Cloudflare.** Cloudflare does not rebuild it for you in this method.

**1. Rebuild locally**

In the project folder, run:

```powershell
npm run build:validate
```

That writes a fresh site into the `dist` folder. That folder **is** the website (HTML, images, sitemaps, `_redirects`).

If you skip this, you would upload yesterday’s files.

**2. Create deployment**

In Cloudflare: **Workers & Pages** → your Pages project (`abicheats`) → **Create deployment** (or **Upload assets** / **Deploy**).

That starts a new live version. It does not pull from Git. You hand it files.

**3. Upload new `dist`**

Zip or drag the **contents** of `dist` (the files inside it: `index.html`, `sitemap.xml`, `_redirects`, and the rest). Deploy.

Cloudflare replaces the old live site with this new upload. The custom domain (`abihacks.com`) stays the same.

**Example:** you edit a blog post, then:

1. `npm run build:validate` on your PC  
2. Cloudflare → Create deployment  
3. Upload the new `dist`  
4. Wait until it says Success  
5. Open `https://abihacks.com` and hard-refresh  

You do **not** run Wrangler. You do **not** need to add the domain again. Only rebuild + upload.

If you later connect the GitHub repo in Pages instead, Cloudflare would build on every push and you would skip the zip upload. Direct Upload is the manual loop above.
